# PAT 串口数据分析集成技术变更路线

> 文档版本：3.1.0　|　决策日期：2026-09-17　|　状态：首版功能开发中，真实设备验收待完成
>
> 依据：[串口数据分析需求](readme.md)、[原设计草案](DESIGN.md)第 9 章、[PAT 当前实现框架](当前实现框架设计.md)。本文是串口分析功能与 PAT 集成的技术选型及实施路线；原设计草案中的 Python 独立应用选型由本文取代，需求和验收口径继续有效。

## 1. 目标与边界

- 首版在 macOS 上交付可直接运行的 PAT 桌面应用，增加串口实时采集、固定帧头/总帧长分帧、协议模板、离线回放、双日志、曲线查看与显示暂停。
- 功能可在 PAT 现有离线解析与界面工作之外并行开发，集成时使用同一格式模型、信号树与曲线交互。旧格式文件和离线打开流程保持兼容。
- 后续按实际需求接入可配置监听地址和端口的 UDP、Linux 无界面入口及 CAN 设备。首版不承诺这些功能。
- 本路线保留架构、改造点、验证和版本规则；具体实现进度以第 6 节及自动验证结果为准。

## 2. 技术选型与模块接口

| 层次 | 选型与职责 | 与 PAT 的关系 |
| --- | --- | --- |
| 构建与语言 | C++20、CMake、Qt 6；沿用现有 `pat_core` / `pat_app` 分层 | 不新增 Python 运行时或第二套 GUI；明确 Qt 6 为集成目标，修正当前名义上的 Qt 5 兼容配置 |
| 协议核心 | `FormatDefinition` 扩展、单帧 `RecordDecoder`、增量 `SerialFrameAssembler`、模板匹配/归类 | 从现有 `RecordParser` 抽取字段解码规则；旧文件解析器继续处理旧格式，串口流先分帧再调用同一解码器 |
| 输入与记录 | `QSerialPort` / `QSerialPortInfo`，后续 `QUdpSocket`；`QFile` 追加原始 `.bin` 与成功解析 `.csv` | 输入、分帧、解码及日志写入离开 UI 线程；数据源只向界面发布批量样本和状态 |
| 数据与展示 | 独立实时会话、有界曲线缓存；复用 `SignalTreeController`、`DisplayGroupManager`、`ChartArea` | 实时会话输出信号定义、样本批次和横轴类型；图表只增量更新，不按每帧重建 |
| 交付 | PAT 的 macOS 应用包；后续独立的 Qt Core/SerialPort/Network 无界面目标 | Linux 入口不链接 Widgets/Charts；共享协议核心和日志能力 |

串口使用 Qt 官方的 [QSerialPort](https://doc.qt.io/qt-6/qserialport.html)，UDP 阶段使用 [QUdpSocket](https://doc.qt.io/qt-6/qudpsocket.html)。Qt Charts 保留作为当前图表实现；[Qt 6.10 起将其标为弃用](https://doc.qt.io/qt-6/whatsnew610.html)，升级绘图库另立任务评估，不作为首版串口集成前置条件。macOS 发布使用 Qt/CMake 应用包及 Qt 部署工具，并在未安装 Qt 的目标机器验证，参见 [Qt macOS 部署文档](https://doc.qt.io/qt-6/macos-deployment.html)。

建议将协议核心、串口输入、实时 UI 分成独立 CMake target，并提供可选的独立试运行入口。并行开发期间，新模块先依赖稳定的接口契约，不直接改动 PAT 的 `MainWindow`、`DataSession` 和图表实现；集成阶段再增加菜单入口、数据适配器和图表增量更新。独立入口与 PAT 应用使用同一份模块代码。

PAT 的信号检索、整体数值平移和差/和子图属于现有信号树及图表体系，并已在 TC-13 集成。I1/I2 阶段的历史约束是不修改这些界面文件；I3 及后续界面变更统一处理 `SignalTreeController`、`ChartArea`、`TrajectoryView` 的交叉改动，并对离线与实时曲线交互做回归验证。

### 接口契约

`ByteChunk(sourceId, bytes)` → `Frame(templateId, rawBytes, completedAt)` → `DecodedFrame(sampleIndex, fields, quality)` → `SampleBatch`。原始字节日志在分帧前写入，成功解析日志在解码后写入；显示暂停只影响 `SampleBatch` 的呈现。`sampleIndex` 只对成功解码的帧递增，同一帧的字段共用序号；多模板会话的序号归属和冲突匹配规则在真实协议样例到位后定稿。

未配置校验的模板只有帧头和定长规则，噪声恰好匹配帧头时无法仅凭这些规则识别误帧。CP01-B3 模板按已提供的协议启用可选 `sum8` 累加和校验；其他 CRC 算法仍需明确规则和样例后实现。“成功解析”表示满足当前模板配置的分帧、可选校验及字段解码规则。应用层读取超时用于无数据告警或重连策略，不作为串口硬件参数。

协议模板沿用 PAT 的 `record_size`、`endianness`、`signals[].byte_offset`、`value_type`、`scale`、`bias`、`unit`、`description`。新格式使用 `schema_version: 2`、`template_id` 和可选 `framing`（帧头、含帧头的总帧长）；旧格式缺少版本号时按现有 PAT 规则读取。串口模板的 `framing.frame_length` 必须与 `record_size` 一致，字段偏移从帧首算起。连接参数与模板分开保存。由原草案到 PAT 格式的映射为 `type → value_type`、`physical_offset → bias`、`byte_order → endianness`、`definition → description`；不直接以两种 JSON 格式长期并存。时间轴规则改为会话属性：旧离线会话沿用时间轴，串口会话使用采样序号轴。

对已知低 8 位累加和协议，可在 `framing.checksum` 中指定 `kind: "sum8"`、`start_byte`、`end_byte` 和 `byte_offset`；三个位置均从帧首按 0 计数，求和范围含首尾字节，校验字节不能落在求和范围内。分帧器丢弃校验失败的候选帧并从下一字节重新查找帧头；原始日志仍保存全部输入字节。

对 `uint8`、`uint16`、`uint32` 字段，可选 `signals[].bit_offset` 和 `bit_width` 提取位段；两者必须同时指定，位 0 是按模板端序解码后的最低有效位。未指定时仍解码完整字段。CP01-B3 按设备回复把状态、告警和故障位段独立显示为十进制整数，同时保留原始字段。未注明分辨率的字段按 1，三项过载单位为 `m/s²`。该模板 ID 升为 `cp01_b3_navigation_output_v2`；新增信号会改变成功解析 CSV 的列集合。

## 3. 技术变更项

| 编号 | 修改项 | 现状与计划 | 完成判据 |
| --- | --- | --- | --- |
| TC-01 | 解码器共用 | `RecordParser::ParseFile` 一次读全文件、按 `record_size` 从头分组；抽出可对单帧调用的解码器，旧离线解析与新流式解析共用 | 已知样例的在线/离线字段值一致，旧格式及旧数据回归通过 |
| TC-02 | 端序与类型 | 格式加载允许 `big`，解码器目前拒绝；补齐大端及协议实际需要的 8 位类型，校验字段边界与比例尺 | 小端/大端、有符号/无符号/浮点及越界样例可验证；未支持类型明确报错 |
| TC-03 | 帧协议与模板 | 新增固定帧头、固定总帧长的跨读取块分帧、噪声跳过、重同步、模板匹配与分类；已知协议可配置 `sum8`，其他校验算法保留扩展点 | 半帧、连续帧、噪声、校验失败、尾部不足帧和冲突模板有确定行为与计数 |
| TC-04 | 数据来源与日志 | 新增串口参数配置、连接状态、后台读取、原始字节 `.bin` 与成功解码 `.csv`（主机时间戳）；回放和实时调用同一协议核心 | 原始日志逐字节等于输入；成功日志行数和值可复核；暂停显示时日志仍写入，写入失败可见 |
| TC-05 | 实时数据与图表 | 新增有界实时会话、批量样本通知和采样序号轴；`ChartArea` 增量刷新，保留现有缩放、平移、分组交互 | 长时运行内存有界；暂停/恢复仅改变显示；原有离线时间轴不受影响 |
| TC-06 | 构建与交付 | 新增可选 SerialPort 依赖和独立模块/试运行入口；集成到 `pat_app`；Linux 阶段再拆无界面目标 | 默认 PAT 构建可用；关闭串口功能时不要求 SerialPort；macOS 包在目标机器可运行 |
| TC-07 | 后续输入 | UDP 保留数据报边界与监听地址/端口；CAN 保留设备 ID、DLC 等元数据，不套用串口帧头扫描 | 各自取得样例和目标环境后设计、验收，首版不计入完成范围 |
| TC-08 | 第 10 章界面改进 | 配置面板由视图菜单控制；暂停时独立统计、图内打散与辅助线、坐标轴和主题优化；按位子信号回归 | 伪终端流、位段值、暂停统计、图表布局与辅助线交互自动测试通过；真实设备与目标机器仍需验收 |
| TC-09 | 版本信息与更新日志 | 帮助菜单提供版本信息和更新日志；版本值来自 CMake，macOS 应用包元数据保持一致；日志作为 Qt 资源随应用打包 | 菜单入口、版本值和离线日志通过 UI 回归；应用包的版本字段与启动可验证 |
| TC-10 | 二维轨迹与空间视图预留 | 复用解码信号与 Qt Charts 绘制可选 X/Y 的离线和实时轨迹；采样配对、可见时刷新和有界抽稀；由 TC-13 扩展为多组二维/三维空间图 | 合成帧与实时缺失字段配对正确；暂停/恢复、切页和绘制点数回归通过；目标机性能单独验收 |
| TC-11 | 显示运算与差值图 | 显示层为单信号提供 LSB 比例和平移；同单位双信号按采样位置生成独立差值序列，离线和实时共用规则；由 TC-13 扩展和值及空间图变换 | 原值与日志不变；组合图、纵轴、光标和辅助线使用显示值；动态追加、暂停恢复、单位与缺失点校验通过 |
| TC-12 | 环境主题与图像辨识度 | 统一窗口控件、时序图和空间轨迹的颜色令牌，提供室内深色、室内亮色和户外高对比三套主题；选择写入本机设置 | 切换后控件、曲线、坐标轴、网格、辅助线和轨迹同步更新；重启保留选择；实时采集路径不重建数据缓存 |
| TC-13 | 统一需求、空间多图与信号检索 | 将原 `PAT功能需求.md` 合入 `DESIGN.md`；空间页动态管理多组二维/三维子图，同维度拖拽合并并保存完整会话历史；信号属性同步作用于空间图；增加和值关系图和独立检索操作区 | 默认二维图、动态新增、同维度合并、跨维度拒绝、源缓存滚动/暂停时历史保留、空间变换、差/和标题来源、检索区直接操作均有自动回归；最长会话内存和真实设备性能现场验收 |
| TC-14 | 自描述日志重构与统一解析 | 新增 VMC 描述表解析；把每个源帧重构成带流 ID、时间戳和定长负载区的固定记录 BIN；`schema_version: 3` 在现有 JSON 上增加流路由和记录时间戳。解析器只向匹配流追加点 | 样本 55 个描述项和 775,975 帧完整遍历；统一记录逐流负载和时间戳往返一致；有效点数与各流统计一致，无字段/记录笛卡尔展开；多文件冲突、重复、时间重置、损坏和取消有确定行为 |

已修正 `CMakeLists.txt` 对 `src/ui/main.cpp` 的大小写引用，并将 GUI 与可单独构建的核心目标分开。文件解析已改为分块读取，但离线曲线结果仍全量驻留内存；离线超大文件的进一步缓存与异步加载可独立推进。

## 4. 并行开发与集成顺序

| 阶段 | 可并行交付 | 与 PAT 汇合的门槛 |
| --- | --- | --- |
| I0 接口与样例 | 确定模板映射、帧样例、数值期望、日志列名和 `SampleBatch` 接口；固定旧格式回归样例 | 契约文档和测试数据进入版本库，未定的校验/模板冲突规则写明 |
| I1 协议核心 | 单帧解码、跨块分帧、原始日志回放、文本导入与帧 TXT/CSV 导出；可用独立入口验证 | 在线与离线处理同一字节流得到相同帧和数值 |
| I2 串口采集 | `QSerialPort` 输入、配置、连接状态、双日志、错误与队列上限；独立入口可运行 | 230400 波特率、100 字节/帧、50 帧/秒下完成持续采集基线 |
| I3 PAT 界面集成 | PAT 新增实时入口和实时会话适配；信号树、分组、曲线交互复用，图表批量刷新 | 离线流程回归通过；暂停绘图时采集和双日志持续；macOS 应用包可独立运行 |
| I4 后续扩展 | UDP、Linux 无界面入口、CAN 按设备资料分别推进 | 各自有独立协议样例、目标平台和验收记录 |

I1/I2 与 PAT 既有需求可以并行；I3 依赖接口契约稳定。首版验收沿用原草案的 1 小时模拟流基线：成功帧数与成功日志行数相同，原始日志与送达应用的输入字节流逐字节一致，图表有界且界面可响应。真实串口设备、字段并发数量和日志保留策略仍需实测/确认。

## 5. 版本与变更管理

- **文档版本**：本文按 `主.次.修订` 编号。架构/接口契约变化升主版本；增加阶段或变更项升次版本；文字澄清升修订号。每次变更同时更新文末记录和 `design_log.md`，注明原因及影响范围。
- **软件版本**：当前 CMake 项目版本为 `0.1.0`（由原 `0.1` 补齐修订位，仍为开发构建），视作现有 PAT 基线；首个完成 I0–I3 验收的集成版本目标为 `0.2.0`。这只是目标版本，完成构建、回归和目标机验收后才修改 CMake 版本并创建 `v0.2.0` Git 标签。UDP/Linux/CAN 的版本号在排期时确定，不提前占用。
- **Git 分支**：文档决策使用 `docs/...`；并行实现按 `feature/serial-core`、`feature/serial-capture`、`feature/live-view` 等主题分支推进。每个分支保持单一职责，合并前核对模板兼容、旧离线回归和新功能验收；提交信息说明变更项编号（如 `TC-03`）。
- **兼容规则**：旧 JSON 无 `schema_version` 时仍按现有 PAT 格式处理；新模板必须标明版本。已发布模板结构需要不兼容修改时升级 `schema_version` 并提供迁移说明。原始 `.bin` 保持无附加信息的字节流，成功 `.csv` 的列名/时间戳规则按版本记录。
- **发布记录**：仅对已完成并验证的发布打 Git 标签；每次发布记录 Git 提交、Qt 版本、目标平台、构建命令、模板版本、已知限制和验收结果。设计文档的版本号不等同于软件已交付版本。
