# 大文件分析重构与验证

日期：2026-09-24；技术路线：3.4.0 / TC-15；软件：0.1.0 开发构建。

## 1. 适用范围与使用方法

| 输入 | 当前读取方式 |
| --- | --- |
| VMC 混合日志 | “文件 → 导入 VMC 混合日志...”后台转换为紧凑 `.patbin` + schema 3 JSON；以后打开 JSON 即可关联 BIN |
| schema 3 索引日志 | 打开只读索引；选信号后后台读取所选流；缩放/平移时按可见时间范围重读 |
| 无帧头、固定记录长度的 `.bin` / `.dat`（schema 1/2） | 预计全部点载荷 `文件大小 / record_size × 字段数 × 16` 超过 64 MiB 时自动建立内存虚拟索引；无须改 JSON、写侧文件或重构原始 BIN |
| 小型旧固定记录文件 | 保持原全量解析方式 |
| 带帧头旧协议 BIN、十六进制文本 | 保持原分帧/文本解析方式；本次尚未为它们建立随机定位索引，大文件解析结果仍会随记录数增长 |
| 串口采集 | 保持现有实时有界缓存、双日志、暂停/恢复及空间历史策略 |

操作入口保持不变：打开格式、打开数据、勾选/搜索信号、合并子图、设置 LSB 比例和平移、创建差/和图及二维/三维轨迹。

- “视图 → 大文件缓存预算”：64、128（默认）、256 MiB；选择立即作用于当前索引查询，本次启动内有效。
- 时序图放大或平移后自动读取新窗口；状态栏显示读取块数、处理记录数、显示点数，以及概览或当前范围原始采样状态。配对任务可能重复读取同一源块，因此处理数是本次各任务处理量之和，不是文件去重记录数。
- 信号右键“当前读取窗口统计...”显示有效点数、最小值、最大值。统计在显示抽稀前计算，包含 JSON 的 `scale`/`bias`，不包含临时显示比例和平移；新查询尚未完成时提示等待。
- 空间页使用全程坐标概览，时序图的局部窗口不会裁掉空间轨迹；切页时可重新按当前预算读取，已有子图和配置保留。全部原始记录保留在磁盘文件中。

## 2. 数据与调度设计

```mermaid
flowchart LR
    A[JSON 与文件索引] --> B[当前信号 / 时间窗 / 预算]
    B --> C[100 ms 请求合并]
    C --> D[单个后台读取任务]
    D --> E[只读相交数据块]
    E --> F[原始统计与时间戳配对]
    F --> G[共同抽稀 / 原始局部样本]
    G --> H[核对会话与请求代次]
    H --> I[更新现有图表]
```

### 查询生命周期

`MixedLoadController` 最多保留一个执行任务和一个最新待执行请求。连续操作合并 100 ms，新请求通知旧任务取消；完成结果必须匹配最新请求代次。工作线程持有会话元数据快照和自己的文件句柄，不操作 QWidget。更换文件、格式或切换实时采集后，旧任务不能覆盖新数据；关闭窗口等待取消后的任务退出。

查询缓存身份包含会话修订号、字段集合、时间窗口、预算与配对定义。更换同尺寸文件也清空旧结果。界面在读取期间保留上次结果，完成后替换样本；读取失败在状态栏报告，并保留上一份成功结果。

`ChartArea::RefreshData` 重绑现有曲线的数据源，保留图表对象及其辅助线、光标、子图高度。主动增删/合并子图仍沿用原布局操作。

### 原始值与抽稀

- 普通曲线逐块解码所选字段，先统计有效原始样本，再按桶保留首点、末点、最小值及最大值，并恢复原始顺序。
- 差/和图通过最多两个流式游标，在同来源段内按原始 `uint64` 时间戳配对，再计算关系并抽稀，关系自身的极值参与保留。不同频率无同时间戳的记录不补零或自动插值。
- 二维/三维坐标最多三个游标，保留同一原始记录组合；各坐标极值所在的整组坐标一起保留。多个空间子图共享字段时合并保留点，不对独立抽稀的列按位置硬配。
- 旧固定记录差/和沿用原横轴容差；空间坐标沿用记录序号配对，兼容字段 `time_scale` 不同的旧模板。
- 局部窗口若相交块记录数超过预算，先计数窗口内匹配记录，再确定抽稀倍率，避免块很大而窗口只有几条数据时仍丢失细节。此时会重复读取相交块，统计 I/O 包含该开销。
- 原始时间戳配对不经过浮点转换；显示横轴仍为 Qt 使用的双精度相对时间。超过双精度可分辨范围的跨度不保证逐 tick 的图上区分。

### I/O 与完整性

统一日志保留原有 `PATMBIN1`、schema 3、CRC32 和结构指纹，未改存储版本。CRC 使用兼容的查表计算，读块时核对块头、索引、长度和 CRC；索引上限 32 MiB，块体上限约 4 MiB 加单条记录余量，先验证尺寸再分配。

普通固定 BIN 的索引只在内存生成，按约 1 MiB 原始记录块定位，不给源文件添加 CRC。末尾不完整记录仍按旧解析器规则忽略。文件发生读取截断会报错。

选中流在来源段内发生时间戳回退或与索引范围不符时读取失败，避免向有序图表提供乱序数据；本次没有增加自动排序或时间重置分段转换。错误时旧成功结果保留，不能将其误认为本次读取成功。

## 3. 性能与内存边界

缓存预算作用于一次查询的结果点容量，在普通曲线和配对任务间分配，并为容器容量预留余量。取消任务会释放工作结果；不会把每条记录展开到所有字段。

**64 MiB 缓存预算不等于整个应用只使用 64 MiB。** 索引、每个游标的块缓冲、元数据、统计、Qt 图表、空间模型，以及新旧结果交接仍占内存。很多空间子图/轨迹也会增加模型和渲染成本；实时完整空间历史仍随会话长度增长。本次没有承诺任意子图数量下的固定进程 RSS。

全程概览需扫描选中流的相关记录，数据扩大 10/20 倍后首次扫描时间仍可能线性增长；读取在后台进行。放大局部只读取相交块，无关流不会被整体解码。当前没有持久化多层概览金字塔，因此再次切换到全程概览可能重新扫描。

单次配对组上限 128；索引/块数量相对预算过大时明确提示缩小范围，不静默突破限制。超过当前索引上限的大型档案需先分段；本次实测覆盖 20 倍样本，不能由此推出任意 TB 规模均已验收。

## 4. 自动验证

标准回归覆盖：

- 核心：旧 JSON、大小端、位段、跨块分帧、日志与显示分离、旧文件与协议样例、CRC 损坏、VMC 往返和真实样本。
- 索引：窗口原始值与统计、无关块不读取、预算变更与窗口缓存失效、同尺寸重开清空、取消、固定记录不同时间比例、跨流缺帧配对、超过 `2^53` 的原始时间戳不误配、差/和极值和三维同步抽稀。
- UI：快速连续窗口请求只显示最新范围、数据刷新保留原时序图对象、差值图局部值、空间页历史切换保留，以及现有图表、主题、检索、实时显示回归。
- 串口：系统伪终端及核心模拟采集；没有使用真实设备替代测试。

## 5. 开发机测量结果

环境：Apple M3、24 GiB 内存、macOS 15.5、Qt 6.11.2、Release；2026-09-24 单次测试，系统文件缓存可能命中。以下为核心测试进程，不包含完整 GUI 的额外内存，也未模拟机械盘/冷缓存。

| 测量项 | 结果 |
| --- | --- |
| 20 倍输入普通路由记录 | 15,519,280 条 |
| 输出统一 BIN | 606,657,596 B，约 578.6 MiB |
| 转换时间 | 8,207 ms |
| 缓存预算 | 64 MiB |
| 概览字段 | 49 个 `ah_nav.*` 字段 |
| 全程概览时间 / 实际读取 | 758 ms / 51,242,240 B |
| 概览保留点 | 1,230,859 点，各字段有效原始样本数校验通过 |
| 局部范围 | 全局横轴最大值的 49.9%–50.0% |
| 局部读取时间 / 实际读取 | 4 ms / 464,828 B |
| 局部保留点 | 16,268 点，未抽稀 |
| 同时差值 + 三维坐标配对 | 1,423 ms / 133,292 个保留点 |
| 核心进程峰值常驻集 | 126,287,872 B，约 120.4 MiB |
| 整个压力用例 | 约 11.17 秒墙钟时间 |

原用例只验证 20 倍转换与索引打开，本次增加实际字段读取、缩放、统计及关系/空间配对。可确认本场景不需要把全部有效数据点展开到数 GiB 内存。最终低性能目标机器仍需使用计划并发信号数、空间子图数及实际磁盘进行验收。
