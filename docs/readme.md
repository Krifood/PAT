# 串口数据分析工具

> 本文从原串口工具工程迁入 PAT，保留原工具用法与初始需求；PAT 集成的技术方案见 [技术变更路线](技术变更路线.md)。下文提到的 `serialtools.html` 位于原工程，尚未迁入 PAT。

在原工程中直接用浏览器打开 `serialtools.html`，无需安装、联网或启动服务。选择原始二进制文件，或粘贴十六进制文本，填入固定帧头和**包含帧头的单帧总长度**，点击“提取数据帧”。

工具会按顺序取出完整帧；可按完整帧内容或帧内指定字节归类。帧结果可下载为 TXT 或 CSV，数据只在本机浏览器中处理。

- TXT 首行是 `帧数据` 表头，之后每帧一行，字节之间用空格分隔，没有统计或其他附加行。
- CSV 首行是 `字节1,字节2,…` 表头，之后每帧一行，每个字节占一列。CSV 使用 UTF-8 编码。
- 分类 TXT 首行是 `分类` 和 `帧数据` 两列表头，之后每帧一行。

十六进制文本支持 `AA 55 01`、`0xAA, 0x55, 0x01`、`AA5501` 等写法。文件格式可手动选择；自动模式把 `.txt`、`.log`、`.hex`、`.csv` 当作十六进制文本，其余文件当作原始二进制。文本中无法识别为十六进制字节的片段会跳过，例如 `接收: AA 55 无效 01` 会解析为 `AA 55 01`；帧头输入仍会严格校验。

## 提取规则

- 从左到右寻找固定帧头；找到后读取指定长度，再从帧尾继续寻找。
- 不足一帧的尾部数据不会输出；无帧头的字节不会输出。
- 当前仅按帧头和固定长度判断，不检查校验和或 CRC。

## 初始需求

1. 给定一组原始字节流顺序，给定固定帧头与数据单帧数据长度，取出数据流中符合要求的数据帧并归类；
2. 将分割后的数据帧以文本格式分行，每个字节内容加空格分割记录；
3. 文本中不能识别成二进制字节数据的内容跳过，不要影响解析；
4. 解析后的数据写一个表头，每一帧数据单独换行存储，不要有多余信息；
5. 支持解析后数据保存为csv；

## 详细需求

1. 支持加载协议模板，给定原始数据对应协议解析方式；
    协议模板内容应包含：
    - 数据端序
    - 数据比例尺
    - 数据偏移量
    - 数据单位
    - 数据定义
2. 支持实时数据输入，同步按照既定协议解析；
3. 实时数据支持串口、can、udp等流式数据协议格式；
4. 同时支持离线数据解析；
5. 实时数据解析后绘图展示（折线图）；
6. 支持选中多组数据同显示；
7. 支持数据处理暂停，绘图数据拖拽，图像缩放；
